# Candidate5 M3 production-arithmetic evidence

This bundle captures CPU-only arithmetic and serializer evidence for immutable candidate5 patch aabff8059c9f50834166bdbbd7b92a2891a2821177719cb21beb9acbb52973a7. It addresses the production arithmetic/integration evidence gap in docs/reviews/FLUTAS_CANDIDATE5_SUCCESSOR_EXACT_REVIEW_20260925T1345Z.md, findings 117–125 and 161–176. The handoff makes no scientific gate disposition.

## What ran

The archived test helper and producer module source are preserved under reference/ and reference/pinned-source/. A focused Fortran harness was generated by build/generate-focused-helper.py; its source is build/candidate5_m3_arithmetic_helper.f90. It links the exact pinned vof.f90 module containing candidate5's restas_source_capture_timestep_inputs and restas_source_record_timestep_restriction, plus an archived no-op source-boundary sanity stub. It does not call the solver or run a source case. The exact successful production-flags compile is compile-command.txt, with full compiler/link invocations in logs/compile-attempt-2.log; the helper runtime command is runtime-command.txt, with raw output and expected statuses in logs/runtime.log, logs/run-*.log, and outputs/.

The compiler was NVHPC nvfortran 26.9-0 / mpif90 with -fast -cuda -acc -gpu=cc120,cuda13.3 (plus the captured preprocessing/module flags). cuobjdump found an sm_120.cubin. The helpers ran as CPU processes with one CPU, a 4 GiB memory limit, no network and no GPU device passed to the container; resource evidence is in logs/container-resource-limits-focused.txt. Compiling a cc120 image is compile/target evidence only; this bundle contains no GPU or CUDA runtime test.

The successful normal case produced a timestep input JSON and restriction CSV. An independent Python binary64 reconstruction of the pinned initgrid.f90 operation order matched 42 spacing and reciprocal entries across four vertical arrays (168 binary64 checks). Independent serialization then matched the exact input JSON bytes and the 15-state timestep CSV bytes. The expected files are in analysis/bundle/; analysis/bundle/independent-arithmetic-report.json records both exact-byte matches and SHA-256 values. A separate 15-state harness emitted index times, while the calculator recorded the difference from an independently accumulated AB2 clock at state 2 in analysis/bundle/time-order.csv.

The reciprocal rejection modes each corrupted one input: scalar inverse mismatch; scalar zero inverse; negative scalar spacing; negative vertical center spacing; zero vertical face inverse; NaN vertical center inverse; infinite vertical face inverse; vertical reciprocal mismatch. Their raw exit statuses, logs and output files are retained under outputs/ and logs/. The ordinary production-flags smallest-subnormal probes for scalar x and vertical face reciprocal both stopped at the “spacings and inverses must be positive” guard. A separately compiled -Mnoflushz diagnostic returned the same guard. NVHPC help captured in logs/nvhpc-help.txt says -fast implies -Mflushz; the result is therefore reported as observed process behavior, without claiming the test establishes which individual floating-point control caused it.

To distinguish this positivity result from the actual reciprocal-overflow comparison, a supplemental helper uses a C shim to clear MXCSR FTZ and DAZ immediately before the same producer capture. With that altered runtime state, each bit-constructed smallest positive subnormal produces an ieee_overflow signal and the exact producer rejects the computed reciprocal against pinned initialization (“scalar inverse spacing differs…” / “vertical inverse spacing differs…”). This diagnostic was compiled with the exact production flags and exact same compiled producer object, but its runtime floating-point control state is deliberately modified. It is not normal production-runtime evidence; commands, shim and outputs are isolated as *-mxcsr-*.

Both nonfinite restriction-result probes exit with the intended error-stop status 1 after emitting CSV. The overflowed rate row has dtic_raw/dtic_used=Inf, dtmax=0, dt_over=Inf; the nonfinite-dt row preserves finite restriction terms but emits dt=Inf, dt_over=Inf. analysis/independent_nonfinite_expectations.py independently composes both expected byte rows; the expected files under analysis/bundle/nonfinite/ exactly match the captured CSVs (hashes in its report).

The frozen analyzer integration is analysis/bundle/analyzer-integration/analyzer-report.json; its command is analysis/analyzer-command.txt. It reports structural/evidence completeness for this offline synthetic fixture with no issue codes, checks 15 actual producer timestep rows, and leaves decision=not_adjudicated and scientific_gate_disposition=none. Phase and velocity tables are synthetic fixture content; source_solver_run=false. This only checks the frozen analyzer's handling of the compiled timestep evidence and is not a full solver bundle or gate review.

## Exact commands and retained attempts

The canonical successful compiler, helper runtime, multistate runtime, independent calculator, nonfinite calculator and analyzer commands are saved in compile-command.txt, runtime-command.txt, runtime-multistate-command.txt, analysis/independent-command-attempt2.txt, analysis/nonfinite-command.txt and analysis/analyzer-command.txt. Every Docker command uses the local image digest, --pull=never --network=none --cpus=1 --memory=4g.

Failed attempts remain archived rather than being overwritten: the original wider harness failed NVHPC OpenACC managed-attribute checks (logs/compile-attempt-1.log); the first expected CSV builder inserted line breaks in no-advance fields (logs/independent-expectations-attempt-1.log); the first multistate launch had a wrapper/entrypoint invocation error (runtime-multistate-command-attempt1.txt, logs/runtime-multistate.log); and the first MXCSR generator attempt failed before the corrected attempt (logs/overflow-probe-mxcsr-generation.log, followed by the successful *-attempt2 artifacts). compile-command-attempt1.txt preserves the first compiler invocation. These failed attempts are not counted as successful tests.
